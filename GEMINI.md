# Gemini CLI - Go CoffeeShop Context

This project is an event-driven microservices coffee shop application built with Go, adhering to Clean Architecture and Domain-Driven Design (DDD) principles. It utilizes a choreography saga pattern for distributed transactions across services.

## Project Overview

- **Core Technologies:**
  - **Language:** Go (Golang)
  - **Microservices:** Barista, Counter, Kitchen, Product, Proxy (gRPC Gateway), Web (Frontend)
  - **Communication:** gRPC for internal, REST (via gRPC-Gateway) for external, RabbitMQ for asynchronous messaging.
  - **Persistence:** PostgreSQL (managed with `sqlc` and `golang-migrate`).
  - **Dependency Injection:** `google/wire`.
  - **Infrastructure:** Docker Compose (local), Nomad, Consul, Vault, Terraform (production-like).

## Architecture & Structure

The project follows a Clean DDD structure within each service under `internal/<service>/`:
- **`app/`**: Application entry point, wiring (DI), and service configuration.
- **`domain/`**: Business logic, aggregate roots, entities, value objects, and domain events.
- **`usecases/`**: Application services/orchestrators.
- **`infras/`**: Infrastructure implementations (Repositories, external clients, etc.).
- **`eventhandlers/`**: Message queue consumers/subscribers.

Shared code resides in `internal/pkg/` and root `pkg/`.

## Key Commands

### Local Development
- **Start all services:** `make docker-compose` (Uses `docker-compose.yaml`)
- **Start core infrastructure only:** `make docker-compose-core` (Postgres, RabbitMQ)
- **Run individual services (Go):**
  - `make run-product`
  - `make run-counter`
  - `make run-barista`
  - `make run-kitchen`
  - `make run-proxy`
  - `make run-web`

### Code Generation
- **Generate Wire DI:** `make wire`
- **Generate SQL Queries:** `make sqlc`
- **Generate Protobuf (using buf):** `buf generate` (Targeting `proto/gen/`)

### Testing & Quality
- **Run tests:** `make test`
- **Linting:** `make linter-golangci`

## Development Conventions

- **DDD Patterns:** Use Aggregate Roots for domain consistency. Domain events are applied via `ApplyDomain`.
- **Database Access:** Prefer `sqlc` for type-safe database interactions. Migrations are in `db/migrations/`.
- **Dependency Injection:** Always update `wire.go` and run `make wire` when adding new dependencies to a service.
- **Logging:** Use `golang.org/x/exp/slog`. A logrus adaptor is available in `pkg/logger`.
- **Protobuf:** Service definitions are in `proto/*.proto`. Use `buf` for linting and generation.
- **Functional Go:** Use `github.com/samber/lo` for collection manipulations.

## Infrastructure Details

- **Postgres:** Multiple schemas (e.g., `order`) are used within the database.
- **RabbitMQ:** Exchanges and queues are used for choreography between services (e.g., `barista-order-updated`).
- **Nomad/Consul:** Deployment scripts and configurations are in `build/nomad/`.
